# 日志上传与拉取

手机端点一次「上传供分析」，维护者 PC 端一条命令拿到可分析的现场。不需要导出文件、不需要转发给任何人。

这一链路是**可选配置**：不配置私有仓库与 token 时，App 一切功能正常，只是没有远程拉日志能力。

## 通道

App 上传目标是一个**私有** Git 仓库（走 Gitee Contents API）。目标仓库在
`local.properties` 里配置（`zr.logOwner` / `zr.logRepo`，编译期注入 BuildConfig，
实现见 `LogUploader.kt`）；自行部署时改成自己的私有仓库即可。

为什么用私有仓库而不是公开对象存储：日志含设备标识、时间线与页面报错文本，
属于可被利用的调试信息；公开桶任何拿到链接的人都能看。

## 上传行为

- 日志按自然小时分块：`diag-YYYYMMDD-HH.log`，一小时写满 8MB 新建续号文件（`.1`），不丢内容。
- 点「上传供分析」上传**当前时刻往前 2 小时**覆盖到的文件，逐个上传到
  `device_logs/<设备>/`；跨小时通常产生 2~3 个云端对象。
- 设置 → 日志文件 里可按日期分组、勾选、上传所选。
- 手机端保留 14 天（`DiagLog.retentionDays`），过期自动清理。

## 凭据

token 按构建类型分开：

| 构建 | token 来源 | 是否进包 |
|---|---|---|
| debug | `local.properties` 的 `zr.logUploadToken` | 是（仅本机自测用，不外发） |
| release | 无 | 否，恒为空串 |

release 包对外分发，谁都能下载解包，所以**绝不把 token 编进 release**。
用户要上传就在设置页粘贴一次，token 只存本机 `SharedPreferences`（`zr_log_upload`），
不随包分发、不进日志。

PC 侧拉取脚本不在开源仓库内（绑定维护者的私有仓库与本地环境）。自行部署时按
Gitee Contents API 实现即可：`GET/PUT /repos/<owner>/<repo>/contents/device_logs/<设备>/<文件>`，
token 经环境变量注入，不要写进脚本。

## 日志内容边界

**隐私模式**（设置 → 诊断日志）：开启后内容类日志（页面文本、JS 执行结果等会话内容）
整体不落盘，只保留事件类别与状态计数。开源渠道在设置页醒目提醒开启；
实现见 `DiagLog.gated` / `SettingsStore.privacyMode`。

其余边界对两种模式一致：

- URL 保留 scheme+host+path，query 与 fragment 一律丢弃（里面有 sid/token/code，属于凭据）。
- 消息体不记；页面文本只记截断后的报错摘要。
- 实现见 `DiagLog.kt` 与 `assets/capture/diag.js`。
